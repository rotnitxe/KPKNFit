## Objetivo
El usuario quiere poder **ajustar lo que importó** antes de guardarlo, para que el programa final quede perfecto. H1 hace la base pura; la interfaz va en H2.
- Hoy la vista previa solo permite decidir qué ejercicio del catálogo es cada nombre («Elegir»/«Propio») y poner título.
- Archivos: `domain/training/importer/{ImportedProgramDraft, ProgramImportParser, ImportedProgramBuilder}.kt`.

## 1. Modelo (`ImportedProgramDraft.kt`)
- **Ids estables.**
  - `ImportedDay` gana `id: String`; `ImportedExercise` gana `id: String`.
  - El parser los asigna de forma determinista: día `w<semana>-d<n>`, ejercicio `w<semana>-d<n>-e<m>`, contando desde 1 y por orden de lectura.
  - Lo que añada el editor lleva `x<contador>`, único dentro del borrador. El contador vive en el borrador: `nextId: Int = 1`.
- `ImportedExercise.sourceText: String? = null`: el texto original de la fila o línea (celdas no vacías unidas con « · »), para mostrar «Tu archivo dice …».
- **Avisos estructurados.**
  - `ImportWarning(id: String, kind: ImportWarningKind, location: String, sourceText: String?, message: String, weekIndex: Int?, dayId: String?, exerciseId: String?)`.
  - `enum class ImportWarningKind { SKIPPED_ROW, IGNORED_VALUE, EMPTY_DAY, NOTHING_FOUND }`.
  - **SKIPPED_ROW:** una fila que se omitió (sin nombre, sin series, sin repeticiones, fuera de rango o «no se entiende»).
  - **IGNORED_VALUE:** el ejercicio se quedó, pero se descartó un valor (carga, %, RPE, RIR o descanso). Lleva su `exerciseId`.
  - **EMPTY_DAY:** un día sin ejercicios, omitido.
  - **NOTHING_FOUND:** no salió ningún ejercicio.
  - `weekIndex` y `dayId` son la semana y el día abiertos cuando se leyó la fila, para que «añadir como ejercicio» sepa dónde ponerlo. Si no había día abierto, `dayId = null`.
- `ImportedProgramDraft.warnings: List<ImportWarning>` y `reviewedWarnings: Set<String> = emptySet()` (ids ignorados o resueltos).
- Para la interfaz de hoy: `val warningMessages: List<String> get() = warnings.map { it.message }`. Los dos usos actuales (`EntrenoProgramImportStep.kt:66` y el de la pantalla de la app) pasan a `warningMessages`, con cambio mínimo.

## 2. Parser (`ProgramImportParser.kt`)
- Rellena ids, `sourceText` y avisos estructurados con su tipo, semana y día. Los textos de `message` NO cambian.
- Todo lo demás se comporta igual: mismas semanas, días, ejercicios y valores para los mismos datos.

## 3. Editor (nuevo `ImportDraftEditor.kt`, puro, sin Android)
Cada operación devuelve un borrador nuevo. Con ids inexistentes devuelve el mismo, nunca lanza.

- **Ejercicio:**
  - `update(draft, exerciseId, patch: ImportExercisePatch, allWeeks: Boolean = false)`.
    - El parche usa `sealed interface Change<out T> { object Keep; data class Set<T>(val value: T); object Clear }`.
    - Campos: `sets`, `repsMin`, `repsMax`, `loadKg`, `percent1Rm`, `rpe`, `rir`, `restSeconds`, `notes`.
    - Poner `loadKg` borra `percent1Rm` y al revés. Poner `rpe` borra `rir` y al revés.
    - Valida como el parser: series 1–12, reps 1–100 con min ≤ max, carga 0,5–`MAX_LOAD_KG`, % 1–`MAX_PERCENT`, RPE 1–10, RIR 0–10, descanso 0–1800. Un valor fuera de rango se descarta (Keep).
    - Con `allWeeks = true`, el mismo parche va a «el mismo ejercicio» en las demás semanas: el que esté en el día de la misma posición dentro de su semana y tenga el mismo `rawName` normalizado. Normaliza con `ExerciseMatchLexicon.normalize`, como el parser. Si no hay, nada.
  - `rename(exerciseId, rawName)`.
  - `remove(exerciseId)`.
  - `duplicate(exerciseId)`: la copia va justo después, con id nuevo.
  - `move(exerciseId, toDayId, toIndex)`.
  - `add(dayId, index, rawName, sets, repsMin, repsMax)`.
- **Día:**
  - `renameDay(dayId, name)`, `removeDay(dayId)`.
  - `moveDay(dayId, toIndex)`: dentro de su semana.
  - `mergeWithNext(dayId)`: los ejercicios del siguiente día de la misma semana pasan al final; el siguiente desaparece.
  - `addDay(weekIndex, name)`: día vacío al final de la semana.
- **Semana:**
  - `removeWeek(index)`: renumera las siguientes.
  - `duplicateWeek(index)`: la copia va justo después, con ids nuevos, y las siguientes se renumeran.
- **Avisos:**
  - `ignoreWarning(warningId)`: entra en `reviewedWarnings`.
  - `addFromWarning(warningId, rawName, sets, repsMin, repsMax)`: añade el ejercicio al final de `dayId`. Si no hay día, crea «Día 1» en `weekIndex` (o en la semana 1) y lo añade ahí. Después marca el aviso como revisado.
- El título no lo toca el editor: ya lo gestiona el ViewModel.

## 4. Revisión final (nuevo `ImportDraftValidation.kt`, puro)
- `check(draft, isDecided: (rawName: String) -> Boolean): List<ImportIssue>`.
- `ImportIssue(kind, weekIndex?, dayId?, exerciseId?, rawName?)`.
- Tipos: `NO_WEEKS`, `EMPTY_WEEK`, `EMPTY_DAY`, `UNDECIDED_EXERCISE` (un nombre sin «Elegir» ni «Propio»; uno por nombre distinto) y `PENDING_WARNINGS` (uno con el número de avisos no revisados).
- `isReady(issues) = issues.isEmpty()`.
