# N3 · Escáner de códigos de barras y alimentos propios

**Prioridad P1 · esfuerzo M.** Informe §4.4 (D6, D7), §1 (decisión 9). Depende de **N2a** (índice `global_foods.sourceRecordId` ya creado en la migración v30) y **H1**.

## Por qué
KPKN no tiene escáner: las dependencias solo traen CameraX, `text-recognition` y `pose-detection` (`app/build.gradle.kts`), y los códigos de barras de Open Food Facts viven en los datos importados (`global_foods.sourceRecordId`) pero nadie los consulta por código. Tampoco hay UI para crear o editar un alimento propio: `NutritionRepository.addCustomFood` no tiene llamadores de UI y además publica antes de persistir. Un escáner local es el camino más rápido y fiable para productos envasados, y es 100 % compatible con «local-first».

## Decisiones ya tomadas (README D1)
- Escaneo **en el dispositivo**, con ML Kit `barcode-scanning` en su variante **empaquetada** (modelo dentro del APK, sin Play Services ni red). Es la única librería nueva autorizada: `com.google.mlkit:barcode-scanning:17.3.0` (si esa versión no resuelve, usa la última 17.x estable y anótalo). Esta corrida puede descargar la dependencia: NO uses `--offline` en la primera compilación tras añadirla. Anota en el informe el cambio de tamaño del APK. CameraX y el permiso `CAMERA` ya están en el proyecto.
- Nada sale del teléfono: ni el código ni la imagen. Sin consulta remota.

### 2. Datos
- `data/db/Daos.kt` (`NutritionDao`): consulta por `sourceRecordId` en `global_foods` (usa el índice de N2a; `LIMIT` pequeño; ordena por `verifiedScore`/`sourcePriority` para elegir la mejor fila si hay duplicados).
- `data/repository/NutritionRepository.kt`:
  - `suspend fun findFoodByBarcode(code: String): BarcodeLookup` con `Found(food, origin)`, `NotFound`, `Invalid`. Orden de búsqueda: alimentos **propios** del usuario (campo `sourceRecordId` = GTIN, ver abajo) → catálogo global. Prueba las variantes de `Gtin.candidates`. Nunca inventes macros: un producto con nutrientes incompletos se devuelve con sus banderas de calidad (`qualityFlags`) para que la UI lo diga.
  - `suspend fun saveCustomFood(food: FoodItem)`, **durable** (espera el commit de Room y solo entonces publica en `foodDatabase`/el índice del resolvedor), y `suspend fun deleteCustomFood(id: String)`. `addCustomFood` existente se conserva para sus usos actuales (caché de IA); no cambies su comportamiento.
- Un alimento propio creado desde un código guarda el GTIN en `FoodItem.sourceRecordId` y `source = "custom"`. Sin migración: son campos que `FoodItem` ya tiene.

### 3. UI
- **Botón de escáner** (icono de código de barras) en el buscador de `screens/nutrition/components/FoodLoggerDrawer.kt`. SIN rediseñar el cajón ni quitar nada.
- **Vista de escáner** (`screens/nutrition/scan/*`): vista previa CameraX + analizador ML Kit; formatos EAN-13/EAN-8/UPC-A/UPC-E; exige el mismo código en 2 fotogramas seguidos antes de aceptar; vibración ligera al detectar; linterna; se detiene tras acertar; libera la cámara al salir (ciclo de vida). Permiso de cámara: explicación + solicitud; si se deniega (o para siempre) queda **solo la entrada manual** (campo para teclear el código, validando el dígito de control).
- **Resultado:**
  - Encontrado → pantalla de confirmación: nombre, marca, **de dónde viene el dato** (propio / base global), banderas de calidad si las hay, y el selector de ración que el cajón ya usa; confirmar lo pasa al flujo normal de registro (el mismo guardado idempotente de siempre; sin caminos nuevos de guardado).
  - No encontrado → «No tengo este producto» + botón «Crear alimento propio con este código» (abre el formulario con el código ya puesto) y «Probar otro».
- **Formulario de alimento propio** (`screens/nutrition/customfood/*`): alta, edición y borrado. Campos: nombre, marca, código de barras (opcional, validado), porción (cantidad y unidad), kcal, proteína, carbohidratos, grasas, y fibra / azúcar / sodio opcionales; base «por porción» o «por 100 g» explícita. Validación pura (finitos, ≥ 0, kcal coherentes con los macros dentro de una tolerancia que avisa pero no bloquea). Guarda con `saveCustomFood`. Los alimentos propios aparecen en la búsqueda y se pueden editar desde el cajón (acceso discreto; refinar, no rediseñar).
- Estilo KPKN v2 (`docs/design/KPKN_UI_V2.md`, `S_COMUN.md`), español, accesibilidad real, objetivos ≥ 48 dp. Hoja de render (PNG, 360 dp, 100 % y 130 %): escáner con permiso, escáner sin permiso (manual), encontrado, no encontrado, formulario vacío, formulario con error.
- Vista previa en dispositivo (COMUN.md): `BarcodeScanHarnessActivity` con `state` = `permission` | `manual` | `found` | `not_found` | `custom_form` | `custom_form_error` y una **fuente de códigos falsa** (el analizador ML Kit se abstrae detrás de una interfaz para poder simular detecciones sin cámara).

- Regresión: los tests de `NutritionRepository*` y del cajón siguen en verde.
